# Thumbnail Renderer

## Current implementation

Thumbnail rendering lives in `mmdbridge-core`; it does not use a browser screenshot, an external MMD installation, PMXEditor automation, or agent-generated images.

The renderer accepts PMX model files, PMX and PMD scene assets, and VMD/VPD Motion assets. X format rendering was retired in G3-04; existing X card files and database history are retained but no longer read, verified, or refreshed by Core. Motion previews use the PMX saved in Settings → Motion Preview Model. VPD applies named local bone translations and rotations; VMD samples bone tracks and vertex, group, bone, UV, material, flip and impulse morphs at the configured preview frame (currently frame 0, falling back to the first mapped Bone/Morph keyframe when frame 0 has none). When a VMD contains camera keys, its interpolated target, rotation, distance, FOV and perspective toggle control the still preview; camera-only VMD files use the configured model with the sampled camera. Orbit position and negated Euler rotation follow the [Three.js r160 MMDLoader camera-animation reference](https://github.com/mrdoob/three.js/blob/r160/examples/jsm/loaders/MMDLoader.js#L1699-L1799). VMDs without camera keys retain standard library framing. The preview frame is saved in the MMDRCV render report. Changing the configured model marks existing Motion cards stale. `Library::render_thumbnail` renders the preview, and `Library::create_card_with_thumbnail` stores the result inside MMDRCV. Desktop card creation enqueues a Core job; CLI `cards create` / `cards refresh` use that Core path. The desktop grid fetches card previews only as they approach the viewport.

For tag-only updates, CLI `cards sync-manifest --asset-id <id>...` calls `Library::create_card(id, None)` for each asset with a current usable thumbnail and reports per-asset failures without rendering a new preview. The command exits unsuccessfully and sets `partialFailure=true` if any item fails. CLI `tags batch-add --name <tag> --asset-id <id>...` uses Core's transactional batch tag API.

The output is 1024×1024 WebP quality 50. Model, VPD, and VMD-without-camera framing is orthographic, using the smaller zoom level from skeleton and mesh bounds for models; scenes instead use a fixed wide-angle perspective camera, looking from -Z toward +Z with +Y up. A VMD camera track replaces that framing with its sampled camera view, including perspective or orthographic projection. PMX material index groups, diffuse / ambient / specular colors, diffuse textures, Toon ramps, multiply / add / UV-space sphere maps, and BDEF1 / BDEF2 / BDEF4 / SDEF / QDEF skinning are supported. VMD previews apply vertex, group, bone, primary UV, material and flip morphs at the selected preview frame. A sampled active impulse morph runs a bounded two-step Rapier rigid-body preview and writes dynamic-body transforms back to the skeleton; this is a still-image approximation, not replay of the full VMD physics timeline. PMX vertex-color materials use the first additional UV channel as color. PMD scene materials use diffuse color, ambient color, specular highlights, their first diffuse texture, sphere maps and Toon ramps; PMD vertices render in their stored rest pose. The renderer report, selected adapter and diagnostics are stored in the MMDRCV manifest. The report records renderer and preview-settings versions. Only a `CardValid` card with matching source fingerprint and renderer/settings versions can supply a cached WebP. WGPU is built with Vulkan and GLES backends; if neither backend exposes an adapter, the renderer returns a structured error.

The current thumbnail settings apply the VPD/VMD pose before calculating motion framing and add a restrained view-facing matcap fill to diffuse shading. Existing MMDRCV thumbnails need regeneration to show these changes. The separate VMD 3D viewer samples Core bone poses continuously at 30 frames per second and provides a timeline and matching camera tracks; its real-time skinning approximates SDEF/QDEF linearly and does not yet animate vertex or material Morphs.

Texture decoding currently accepts BMP, JPEG, PNG and TGA, resizing textures to the device-reported 2D limit capped at 4096 pixels on their longest edge. Missing diffuse / sphere textures use the white fallback and record a diagnostic; a missing default Toon image uses the corresponding built-in MMD Toon PNG from Three.js MMDLoader r160, while custom Toon files are loaded directly. PMX shared Toon indices follow the standard toon01-to-toon10 mapping. Impulse preview starts from the sampled pose and applies active impulses for two fixed 1/65-second steps; it does not replay earlier VMD frames, so motion-dependent results may differ from MMD applications. Joint types and collision behavior are approximated by Rapier. VMD camera tracks are rendered at one selected still frame, without timeline playback; VMD light animation is not applied. The camera preview uses the square thumbnail aspect ratio, so framing can differ from a widescreen MMD viewport. Additional UV channels beyond channel zero and edge / point / line drawing are not rendered. Retired X records cannot create new Core cards.

The built-in toon00-to-toon06 PNGs are copied from [Three.js r160 `MMDLoader.js`](https://github.com/mrdoob/three.js/blob/r160/examples/jsm/loaders/MMDLoader.js#L364-L381), © 2010–2023 Three.js Authors, under the [MIT License](https://github.com/mrdoob/three.js/blob/r160/LICENSE).

## Queue and cache

Character PMX thumbnails compare skeleton and mesh framing and use the smaller zoom level. Scene PMX and PMD thumbnails use a 90° perspective camera at world center, 165 cm above the floor (20.625 MMD units), looking toward -Z; their own scene preview version lets model and motion cards retain their cache. Cutout textures use alpha masking so hair and clothing edges write depth, while fractional transparency still uses blending.

The Core persists thumbnail jobs in SQLite with `Pending`, `Parsing`, `Rendering`, `Encoding`, `Completed`, `Failed` and `Cancelled` states. It supports priority, batch enqueue, cancellation and retry. A 24-thread Core pool selects the highest-priority pending tasks, while independent Parse, Render and Encode gates enforce stage caps. Settings → 缩略图阶段并发上限 supports Auto, 1, 2, 4, 8 and custom values from 1 to 8; changes apply immediately. Auto uses up to 8 CPU workers for Parse and Encode, and one Render worker to limit GPU contention. Pending tasks are persisted in SQLite and the in-process priority queue can hold a large library batch. Pending work resumes when the desktop Library opens; a conditional database claim prevents two Core clients from processing the same queued job. Cancellation is checked while waiting for a stage slot and between stages; an active GPU draw cannot be interrupted mid-command. The desktop job bar polls progress and exposes cancel / retry actions. CLI `thumbnail enqueue` and `thumbnail batch` wait for terminal job results before exiting, so their background work is not lost with the CLI process.

Cache eligibility uses the scanned primary-source fingerprint plus the renderer and preview-settings versions stored in the manifest. The scanner also checks indexed package dependencies by size and modified time; if one changes, its card remains `CardStale` through verification and must be rendered again before it can supply a cached WebP. Schema v13 records each verified MMDRCV's file size/mtime and current manifest/renderer revisions. Routine scans use those stamps to skip reading unchanged card archives and their previews; missing, stale, changed, or not-yet-cached cards still receive deep verification, and the explicit “校验” action always performs a deep check. The first scan after upgrading fills the v13 cache fields. Unsupported source formats fail thumbnail jobs with a structured error; a user can still create a metadata-only MMDRCV card from the desktop action.

Pure-Camera VMDs are auxiliary and are excluded from normal card discovery, direct card access, and thumbnail enqueue/retry. The schema v12 migration cancels their unfinished thumbnail jobs but leaves existing card files and historical tags/favorites in place; pairing and motion preview continue to read their source VMDs through the relation index.

## Smoke evidence (2026-09-25)

- Core and CLI compile with `cargo check -p mmdbridge-core -p mmdbridge-cli --offline`.
- Desktop frontend compiles with `npm run build`; it was rerun after updating the Motion Preview settings explanation for camera tracks.
- Tauri compiles with `cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml --offline`.
- A real `EMT.pmx` sample rendered on `NVIDIA GeForce RTX 4090 (Vulkan/DiscreteGpu)`: 21,927 vertices, 36,689 triangles, 21 materials, 1024×1024 WebP, 10,916 encoded bytes.
- A temporary Library scan → render → MMDRCV write → verify → thumbnail read flow returned `CardValid`, `hasThumbnail=true`, and 10,916 preview bytes.
- The sample folder did not include the PMX's referenced `data\...` textures. The report listed those missing paths and Toon-map limits; the image showed the model silhouette with fallback materials.
- The Core queue completed a PMX job, persisted a cancelled job, retried it to `Completed`, and verified the resulting `CardValid` card and embedded preview. The retry reused the matching card cache.
- Before G3-04 retired X support, a real text-X Scene sample rendered with 72 vertices, 24 triangles, one material and one loaded texture. After changing the indexed texture dependency, a rescan left the card `CardStale`; card refresh rerendered it and returned `CardValid`.
- Before G3-04 retired X support, a real binary `BOX-stage15.x` scene rendered headlessly on the RTX 4090/Vulkan adapter: 2,376 vertices, 792 triangles, two materials, two loaded textures and a 5,182-byte 1024×1024 WebP. Its 4,000-pixel texture was resized to the renderer device's supported texture limit.
- A real `楪いのり.pmd` scene rendered with 43,448 vertices, 78,654 triangles, 22 materials and 11 loaded textures as a 1024×1024 WebP.
- A real `pose.vpd` and `Tda Aoki Append.pmx` pair rendered through an in-memory Library without writing beside the source assets: 25,157 vertices, 36,105 triangles, 1024×1024 WebP. The 163-bone pose produced no unmapped, ambiguous or invalid bone diagnostics.
- A real `sample_motion_miku.vmd` rendered against `Tda Aoki Append.pmx` at frame 0: 80 mapped bone tracks, 283 unmapped source bone frames and the active `まばたき` vertex morph (`AppliedVmdVertexMorphTracks:1`), producing a 1024×1024 WebP.
- Renderer 0.4.0 rendered a real `Camera.vmd` against the configured preview model at frame 0 with no model-motion channels; it produced a 1024×1024 rest-pose preview before camera-track rendering was added.
- After renderer 0.2.0 material changes, a real `YYBmikubase.pmx` rendered on `NVIDIA GeForce RTX 4090 (Vulkan/DiscreteGpu)`: 35,300 vertices, 59,696 triangles, 18 materials, 13 loaded textures and a 23,224-byte WebP. The source directory lacked two referenced `tex/C.png` files; the report listed them. The image was inspected locally without opening the desktop application.
- Renderer 0.3.0 rerendered the same real `YYBmikubase.pmx` headlessly on the RTX 4090/Vulkan adapter and decoded the output as a 1024×1024 image. It produced the same 35,300 vertices, 59,696 triangles and 23,224-byte WebP; the only missing-resource diagnostics were the two source `tex/C.png` references.
- A real 54-material PMX with shared Toon indices 0, 1 and 9 rendered headlessly on the RTX 4090/Vulkan adapter. The 71,858-vertex, 110,785-triangle model produced a 14,814-byte WebP with no Toon decode errors; its diagnostics were limited to three unsupported non-triangle styles.
- Renderer 0.4.0 Core and CLI compile-checked after adding the bounded Rapier impulse-morph preview. A real PMX/VMD pair containing an active impulse morph has not yet been rendered to compare its result with an MMD application.
- Renderer 0.5.0 rendered a real camera-only `Camera.vmd` against a PMX through an in-memory Library on `NVIDIA GeForce RTX 4090 (Vulkan/DiscreteGpu)`: 71,858 vertices, 110,785 triangles, perspective projection at FOV 30, and a 15,918-byte 1024×1024 WebP. The image was inspected locally; its framing follows the VMD camera at frame 0. The smoke path did not open or control a desktop window.

The earlier smoke does not prove the default view is PMXEditor-front-facing. The current report labels `+Z` as provisional. No PMXEditor golden comparison has been completed; the newer YYB sample loaded 13 textures but still lacked two referenced files.

## Candidate investigation

The external MDanceIO 0.1.2 offscreen renderer compiled on Windows, but it did not load either of the two real PMX samples used for the runtime check: `REM式プロセカ風初音ミクVS.pmx` failed with `ModelMorphCorrupted`, and `EMT.pmx` failed with `BufferEnd`. Neither run produced an image. This does not establish that the source files are malformed.

The existing `mmd-anim-format` parser and `mmd-anim-runtime` both parsed and evaluated those same files successfully with zero parser diagnostics (72,354 / 21,927 vertices and 802 / 389 evaluated bones), so Core uses that parser/runtime path instead of adding a second PMX parser.
