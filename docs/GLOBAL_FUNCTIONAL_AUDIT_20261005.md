# 全局功能逻辑检查与回归计划（2026-10-05）

## 检查目标与边界

覆盖 Library → Core → Tauri / CLI → React 的功能链路，优先检查并发请求、取消、重试、跨入口操作、过期数据和文件操作确认之间的冲突。保持现有玻璃界面和系统明暗行为，不添加宣传文案。真实资产不参与写入或删除验证；需要文件的 Rust 用例只使用唯一命名的临时目录。

此次采用分层验证：源码逻辑检查、可重复的回归用例、前端生产构建、独立浏览器的示例数据交互，以及 Windows / Linux CI。示例桥接数据只验证前端状态和操作入口，不能证明 Core、Windows Shell 或真实 GPU 的行为。

## 已修复的问题

1. **同步扫描和后台扫描竞争。** `scan_root` 原先排入后台队列后又尝试自己领取，可能被后台线程抢走。同步入口现在只记录任务并同步领取。
2. **任务去重与重试不是原子操作。** 新建与重试统一在 SQLite Immediate 事务内检查活跃任务和文件操作。批量提交先验证全部资产、再一次性保留和派发任务，避免返回错误后仍留下部分新任务。
3. **取消过早释放占用。** 运行任务先进入 `Cancelling`，完成更新不能覆盖它；实际领取任务的线程退出后才确认 `Cancelled`。未领取成功的重复队列项不能确认取消。界面计数、轮询、禁用按钮、文件操作和压缩检查均识别该状态。
4. **重启恢复可能重复执行活任务。** 缩略图记录进程 PID，并复用现有扫描的进程存活检查。活进程即使超过原 10 分钟阈值也不会被恢复；死进程可恢复，取消中的死任务直接终结。活进程的文件操作日志不再被另一个入口标为中断。
5. **文件操作与扫描、卡发布及其他文件操作存在检查间隙。** 事务内登记任务、资产、根目录和路径占用；登记后重新验证确认计划；扫描领取和根目录移除检查占用；新缩略图和卡发布检查进行中或待恢复的操作。目标路径相同、大小写等价或互相嵌套的不同资产操作被拒绝。
6. **旧预览可能绑定到新资产版本。** 卡发布保留渲染开始时捕获的资产指纹和路径，检查预览设置版本，并在发布事务中再次检查资产、路径及文件操作状态。
7. **超时后旧资产重新出现、隐藏的批量选择遗留。** 读取超时或失败清空旧列表与选择，成功刷新修剪不可见目标，切换递归范围或视图也清除批量选择。
8. **文件夹往返遗漏快捷筛选，偏好存储异常导致白屏。** 返回快照新增标签、组合方式、骨架和递归范围，校验旧快照；不可用或容量不足的存储使用当前窗口内的偏好回退。
9. **旧动作请求干扰新查看器。** 帧请求使用独立的串行合并队列，丢弃过期帧和关闭后的响应 / 错误，失败后允许重试。
10. **数据库兼容性与空间信息错误。** 写入 PRAGMA 和迁移前拒绝未来版本，新增结构版本 16 的 `jobs.claim_owner` 与索引；空间信息使用实际打开的数据库及其 WAL，不再固定报告默认库。

## 迁移与剩余验证范围

- 结构版本从 15 升到 16，迁移不删除资产、任务或设置。旧版程序不能打开未来版本；已经迁移的库应继续使用本次或更新的程序。
- PID 检查复用已有实现，不是完整的跨进程租约协议：PID 重用或无法查询进程时会保守保留占用。版本 15 遗留的无 PID 活跃任务仍使用原 10 分钟恢复阈值。
- 外部程序仍能改变磁盘文件。本次沿用快照确认和操作日志，无法保证任意外部修改发生在最后一次检查之后也被完全阻止。
- 未启动用户桌面程序、未操作前台窗口、未写入或删除真实资产。Windows 回收站执行、真实 PMX / VMD GPU 渲染、WebView 字体与动画、真实 Unicode 长路径和便携 EXE 实机运行仍需独立验证。
- 全局检查覆盖功能链路与高风险交界，并不表示所有输入组合或所有漏洞均已排除。
