# MMDbridgeLib 第二轮功能排查与改进目标

日期：2026-09-27

交付性质：排查报告与后续实施规格；本文中的修复方案尚未实施。

## 1. 结论与证据边界

项目已经具备资产管理器的主要骨架：Rust Core、SQLite、递归扫描、资源卡、原生缩略图渲染、后台队列、搜索与智能集合、标签和收藏、关系和重复项、资产包操作、PMX 权重查看、场景查看与 VMD 播放。第二轮应优先把这些能力连接成可靠、可理解、可恢复的日常工作流，不需要整体推倒重写。

当前最重要的问题是：**资产操作的依赖检查存在漏检；扫描写入缺少单资产事务；后台任务与恢复流程没有统一的进程所有权；部分界面行为与 Core 能力脱节。** 这些问题应先于视觉装饰和更多格式支持处理。

本次采用需求与源码交叉检查，覆盖所有主要产品功能及其 Core、Tauri、CLI、UI 入口，但不是逐行形式化验证，也不代表已经找出全部缺陷。没有启动桌面程序、浏览器、MMD 或 PMXEditor；没有执行真实资产扫描、生成卡片、移动或删除；没有读取或修改便携版数据库；没有运行编译、全套测试或 SHA 校验。仅新增本文件。

证据标记：

- **[确认]**：当前源码明确存在该行为或缺少该入口；不等于已经实机复现其所有后果。
- **[风险]**：调用链存在可能失败的条件，仍需要限定场景验证；不表述为已发生数据损坏。
- **[缺口]**：原始目标或已补充要求尚未闭环。
- **[设计]**：基于当前 JSX、CSS 与工作流提出的易用性调整，不是截图审计或用户测试结论。
- **[待验]**：必须通过离屏运行或经用户安排的安全 UI 验证才能判断。

既有 `docs/` 中的历史运行记录只用于了解过去覆盖过什么，不计为本轮验证结果。当前源码与旧文档冲突时，以源码描述现状，并把冲突本身列入修改项。

## 2. 实施原则与优先级

1. 继续以 `MMDbridgeLib_Goal_v1.md` 为产品需求总表，用户后续要求及 `AGENTS.md` 优先。本文不取消原目标，也不把待完成项目改成“已支持”。
2. 复用 `mmd-anim-format`、`mmd-anim-runtime`、现有 wgpu 渲染器、Three.js 显示层、VirtuosoGrid、SQLite、Core 操作计划和日志。前端不再增加一套资产判断规则。
3. 优先小而完整的修复。新增跨进程任务所有权、持久复核模型、预览协议扩展等中型以上变更，先提交具体数据结构和迁移范围供确认；已有明确批准的资产包操作、阶段并发、二进制 X、指定 Morph 和相机静帧范围不重复索要授权。
4. 不改动源素材来掩盖解析或预览问题。写操作继续使用计划、确认、执行、日志；真实素材验证只读原件，必要写入使用唯一临时副本。
5. 保留现有 BLAKE3 资产身份机制，不引入 SHA 校验，不做无目的的全库重新指纹计算。
6. 基础信息、缩略图、资源卡由软件/Core 生成；Agent 标签工作只在明确要求后执行。
7. QDEF 现有能力保留，真实 QDEF 素材搜寻与实机验证不设为交付门槛。

优先级：P0 为文件安全或持久数据一致性；P1 为核心工作流正确性、恢复和可用性；P2 为效率与体验完善；P3 为增强功能。改动规模：S 为局部修改，M 为跨层或小型迁移，L 为新机制或协议改造。规模用于安排实施，不代表本文授权立即改代码。
