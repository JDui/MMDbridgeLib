# Goal 2 · D｜解析、预览与关系

## 本册目标与完成条件

- 目标：先统一元数据、卡片与查看器口径；视觉真伪通过少量代表性素材与安全安排的 UI 验证，不把编译或非空图片当视觉验收。
- 批次完成条件：动作区间和镜头关系一致；X 层级变换只应用一次；manifest 变化不强制重绘；已知渲染限制如实显示。
- 证据级别沿用原排查文档；静态确认不等于运行验证。每项先核对当前源码是否已变化，若已修复，记录证据后跳过重复实现。
- 本册原有条目文本完整保留，下面的“执行契约”补充可交付边界；与用户最新要求或根目录 `AGENTS.md` 冲突时以后者为准。

**范围/验收**：S/M。只用一份首关键帧不在 0 的 VMD 和一个 VPD，核对区间、实际预览帧与 Pose 修正的保存。

### G2-06：场景解析、X 支持和面积

**证据**：`parser.rs` 场景分支、`x_binary.rs::collect_meshes/parse_mesh`、`thumbnail.rs::render_input_from_x`；`docs/THUMBNAIL_RENDERER.md` 的限制说明。

**现状**：PMX、PMD、文本 X、无压缩二进制 X 已有解析/渲染路径；面积采用原 MMD 单位的 XZ 包围盒，不能显示为平方米。

**修改方案**：

1. [确认] 当前 X 不应用 Frame 层级矩阵。将层级变换在 Core 的统一场景几何入口应用一次，元数据包围盒、缩略图、3D payload 使用相同结果；法线按对应矩阵处理，防止重复应用。
2. [待验] X 多边形 `face_count` 与实际三角索引数可能含义不同。统一 `polygon_count` 展示口径为三角面数，必要时另保留原多边形面数。
3. [设计] 显示格式与能力原因：无压缩二进制、压缩不支持、无网格、部分对象未应用。失败时不把全部资产称为“损坏”。
4. [缺口] unsupported 资产保留元数据卡的入口，并显示为何不能生成缩略图；当前队列跳过 Unsupported，不能让用户只看到“0 项完成”却不知道原因。
5. [待验] 退化包围盒、非有限坐标、超大范围返回可理解诊断，避免前端出现无穷尺寸。

**范围/验收**：X 变换 M；扩展压缩 X 另列 L，先确认需要。采用一个带两级 FrameTransformMatrix 的小样本验证位置与面积，复用现有二进制解码器，不引入第二个 X 解析器。

#### G2-06 执行契约

- X 的层级 FrameTransformMatrix 在 Core 几何入口组合一次，元数据、封面和 3D payload 复用同一顶点坐标。
- 法线使用正确逆转置或等效处理；非有限值、退化几何和无网格要返回具体能力/错误状态。

### G2-08：MMDRCV 写入、校验、缓存和一致性

**证据**：`cards.rs::create/verify/cached_thumbnail/read_card/choose_target/publish_card`、`database.rs::create_card_with_thumbnail_progress`。

**保留**：ZIP 容器、manifest/preview、限长读取、文件名安全、同名冲突 ID 后缀、临时文件验证后发布、替换前归属检查、源指纹验证。不要另写一个卡片打包脚本。

**修改方案**：

1. [确认] `cached_thumbnail` 要求整个 CardValid，标签/收藏变化把卡标记 Stale 后会导致普通刷新重绘。把“manifest 需要同步”和“图像需要重绘”分开；manifest-only 路径复用 `Library::create_card(id, None)`。
2. 渲染键明确包含主文件版本、依赖变更版本、renderer 版本、预览模型及其依赖、预览设置。以已知依赖的 size/mtime 或扫描 revision 为常规失效依据，不增加 SHA 或默认全库指纹。
3. [风险] 渲染使用一个源版本，写卡时重新读取当前数据库上下文；若同时重扫，可能把旧图与新指纹/元数据组合。渲染开始捕获 source/render revision，发布前比较，变化则丢弃结果并重新排队。
4. [确认] 目前 tags 只保存字符串，来源和 confidence 无法从卡恢复，详见 G2-16。卡片协议采用可选扩展字段，仍兼容 schema 1。
5. [设计] 详情显示卡路径、状态原因、最后生成时间、渲染限制与“同步资料/重绘预览”两个动作。CardValid 但无 preview 应显示“资料有效，预览未生成”。
6. [风险] 卡文件发布成功后数据库更新失败属于双存储部分成功。错误应说明“卡已写入、索引待同步”，下次校验从旁车恢复；不要提示用户反复覆盖文件。

**范围/验收**：S/M。一个标签变更只更新 manifest 并保留预览；一次源版本变化应拒绝旧渲染结果发布；重用现有卡校验断言，不测试所有 ZIP 组合。

#### G2-08 执行契约

- 分别维护源/预览版本和 manifest 整理版本；标签、收藏等仅改变 manifest 时复用现有图像字节。
- 渲染开始捕获版本，发布前再比较；版本改变则废弃旧结果并重排，绝不把旧图写成新源的卡。
- 卡已发布而索引更新失败时保留部分成功诊断，下一次校验恢复索引；旧 schema 1 卡片仍可读。
- **交付记录**：列出涉及文件、旧/新行为、实际执行的最小验证、失败或未验项；仅满足本节原有验收并给出证据后标记完成。

**修改方案**：

### G2-11：VMD 播放、相机与预览模型

**证据**：`motion_view.rs::paired_camera_path/create_session/frame`、`MotionViewer.tsx::requestFrame/applyFrame/setAnimationLoop`。

**问题与改法**：

1. [确认] 配套相机 SQL 要求 `camera.asset_directory=当前动作目录`，把关系识别得到的子目录镜头排除。按已存关系选相机，确认关系优先，其次候选分数；让用户可从候选中切换，复用 G2-17。
2. [确认] 每次渲染循环满足间隔才 `frame+1`，慢 IPC 时不会追赶时间。改为基于起始帧、单调时钟、速度算目标帧；保留“一次在途、后来的目标覆盖旧目标”，性能不足跳过显示帧但不拖慢时间。暂停、拖动、循环重建时间基准。
3. [确认] viewer 的 max_frame 只统计 Bone/Morph/Camera，与 parser 含 Light/IK/Self Shadow 的结束帧口径不同。优先使用 Core 统一时间范围，说明未显示的通道。
4. [缺口] 缺预览模型时现在只报错。提供“选择 PMX 预览模型”动作，保存后自动重试当前动作；模型失效时保留原设置并提示重新定位。
5. [确认] 实时使用线性蒙皮近似 SDEF/QDEF，Morph 和完整物理未实时显示。保留能力提示；真正补齐时扩展 Core frame payload 并复用现有 Morph/蒙皮实现，不能在前端重写 VMD 解析。
6. [风险] 请求生命周期缺少资产/session revision；关闭、换动作或换模型后旧回包不得应用到新场景。收到骨骼数量不符时明确报协议错误，而不是静默 return。
7. [设计] 加帧输入、秒显示、上一/下一帧、重播、循环开关、复位镜头、空格播放（输入框内不触发）。VPD 可提供单姿势预览入口，复用 Core VPD 解析，时间轴禁用并解释。

**范围/验收**：镜头与时钟 S/M；实时变形完整性 L，需确认方案。最低验证为子目录 Camera 关系可选、慢帧返回下播放时长正确、快速拖动最终停在最后目标帧。

4. [确认] 确认关系会保留，但 `versions` 每次清空重建。手动版本族应与自动族分开持久化，不能把用户分组重新推断掉。
5. [设计] 版本族展示主条目＋成员列表和版本标签，不必把每对成员都变成详情卡；减少同族 N² 关系在大族中的存储与阅读负担。

**范围/验收**：M。一个动作配同目录与子目录两份镜头，确认一份、拒绝一份，再重扫仍保持；版本族成员变化不丢人工选择。

#### G2-17 执行契约

- 人工 accept/reject/unset 以稳定关系键持久化；自动重建仅刷新建议，不重置人工判断。
- Core resolver 同时服务查看器、详情与筛选，解释已确认、候选和无镜头三种结果。
- 版本族人工分组独立于自动族；成员改变时保留人工决定并标出悬空引用供复核。
- **交付记录**：列出涉及文件、旧/新行为、实际执行的最小验证、失败或未验项；仅满足本节原有验收并给出证据后标记完成。
