# Goal 2 · C｜Library 浏览与整理

## 本册目标与完成条件

- 目标：保留现有 Core 查询、游标分页和虚拟网格，先修复刷新与最小窗口的明确问题，再扩展筛选和整理保真。
- 批次完成条件：深页选择、滚动与图像更新正确；筛选语义一致；用户整理结果有明确的卡片同步状态；设置在合法最小窗口可达。
- 证据级别沿用原排查文档；静态确认不等于运行验证。每项先核对当前源码是否已变化，若已修复，记录证据后跳过重复实现。
- 本册原有条目文本完整保留，下面的“执行契约”补充可交付边界；与用户最新要求或根目录 `AGENTS.md` 冲突时以后者为准。

## 任务与执行契约

### G2-13：Library 刷新、分页、详情与缩略图更新

**证据**：`App.tsx::refresh/loadNextAssetPage/CardThumbnail`，当前页大小 `LIBRARY_PAGE_SIZE=120`。

**问题**：

- [确认] 收藏、标签、任务完成等调用全局 refresh，替换为首批 120 项，并只从这一批找回 selected；已滚动到后续页的选中资产会丢失。
- [确认] CardThumbnail 的 effect 只依赖 assetId，卡图更新但组件未重挂时可继续显示旧 Blob。
- [确认] 详情标签/关系/重复 effect 只依赖 selected.id；同 ID 的重扫更新不会自动重取这些字段。切换资产时也没有立即清空旧详情数据的独立加载状态。
- [风险] 类型或 Root 切换期间旧列表仍可能短暂保留；虽然已有 revision 防旧请求回写，但局部加载/错误状态尚未完整区分。

**修改方案**：

1. 将“查询条件变化”和“当前数据更新”分开。前者重置分页，后者更新受影响 ID 并保留已加载页、滚动锚点和选择；资产退出当前筛选时再明确移除。
2. 详情按 ID 独立 inspect，不依赖当前首批列表。为元数据、标签、关系分别维护 revision 或受影响事件，防止显示另一个资产的旧数据。
3. Core 返回 `thumbnailRevision/cardUpdatedAt`；缩略图缓存键为 ID＋图像版本，替换后销毁旧 Blob，失败可重试。不要用每次 render 的随机 key 强制重载。
4. 已有 revision 和游标分页继续复用；库变化导致排序移动时标记分页失效并保留可见锚点，不追加前后不一致的游标结果。
5. 大批任务逐项完成时限频刷新可见卡片，不等最后一个任务才更新，也不对每个完成事件重载整库。

**范围/验收**：M。第 3 页选择一个资产后收藏/加标签/刷新卡，仍停在该资产且新图可见；快速切换筛选不出现旧结果。

#### G2-13 执行契约

- 查询条件变化才能重置分页；单资产数据变化按 ID 局部更新，并保留已加载页、选择和滚动锚点。
- 详情独立按 ID 和数据 revision 获取；切换资产立即显示加载态，禁止旧请求覆盖新选择。
- 图像缓存键包含 thumbnailRevision，替换时释放旧 Blob；排序变化导致游标失效时明确重定位锚点。
- **交付记录**：列出涉及文件、旧/新行为、实际执行的最小验证、失败或未验项；仅满足本节原有验收并给出证据后标记完成。

### G2-14：搜索、排序、目录浏览和数量口径

**证据**：`scanner.rs::ASSET_SEARCH_PREDICATE/search_query_parameter/list_asset_page`；`App.tsx::submitSearch/childFolders/indexedTotal`。

**现状**：名称、路径、标签空格 AND 匹配、NFC/NFD 变体、LIKE 特殊字符转义、Core 游标分页、按目录及后代过滤均已有实现。

**修改方案**：

1. [设计] 搜索框明确当前范围，提交后显示搜索词和清除操作。实时搜索如需加入，使用短防抖及已有 revision；保留 Enter 立即提交。
2. [缺口] 增加名称、最近添加、最近修改等排序，Core 参数白名单与游标同步升级；不得只给当前 120 项做前端排序。
3. [确认] 收藏数和筛选结果部分使用已加载数量。区分总匹配数与已加载数；需要总数时用同一筛选表达式 count，避免 UI 各算一套。
4. [设计] 目录明确“包含子目录”，保留面包屑并加返回上级。子目录按钮不宜无限铺满首屏；大量文件夹可折叠或分页。
5. [确认] 每次 refresh 取 Root 全部目录，再由前端遍历分组。先缓存，规模确实影响响应后扩展 Core `child_directories(root,parent)`，路径归属和计数归 Core。
6. [缺口] 模糊搜索尚未实现。先衡量现有本地 LIKE 查询的响应，再决定是否启用 SQLite 现有索引/FTS 或轻量候选评分；不先引入搜索服务器。

**范围/验收**：S/M。一个中文、日文、空格多词与 `%/_` 路径用例；目录进入/返回与分页排序保持正确。不要求每次修改跑 5 万资产基准。

#### G2-14 执行契约

- Core 对排序字段采用白名单并将排序键与 asset ID 一起纳入游标；不能只对前 120 项排序。
- 总匹配数与已加载数分开；搜索词、目录后代范围和 count 使用同一筛选表达式。
- 中文、日文、空格多词和 LIKE 特殊字符维持现有正确性；模糊搜索先测现有查询再决定方案。
- **交付记录**：列出涉及文件、旧/新行为、实际执行的最小验证、失败或未验项；仅满足本节原有验收并给出证据后标记完成。

### G2-15：筛选与智能集合

**证据**：`filters.rs::compile/save/apply_page`、`App.tsx::saveSmartFilter/changeFilterField`、Tauri `assets_page`。

**问题与改法**：

1. [确认] UI 只能平铺一个 AND/OR 组和逐条 NOT，保存总是 `filterId:null`；Core 已支持嵌套和更新。先补“应用而不保存”“编辑现有”“另存为”，复用 `filter_save`。
2. [确认] 切换到 cardStatus 时草稿值为空，但 select 没有空选项，可能显示首项而保存仍报空。所有枚举字段初始化为真实默认值，或显式“请选择”。
3. [确认] Tauri 使用 filterId 时走单独 apply_page，没有合并其余所有普通筛选参数。先明确 UI 是否允许叠加；允许时在 Core 合并条件，禁止时禁用并解释，不能看似生效却忽略。
4. [缺口] 原目标有 Version Family 筛选，现有 FilterField 未包含。补版本族、复核原因与精确/可能重复类别，不用把元数据 JSON 暴露给普通用户。
5. [设计] Root、标签提供选择器，数值显示单位，日期提供“最近 7 天”等相对条件。复杂嵌套用最多几层分组编辑，不降低 Core 已有深度/节点限制。
6. [待验] 类型不适用和缺失元数据的 NOT/不等于语义需要定义：例如“非 Camera”是否包含模型。明确空值规则再补一个代表性测试。

**范围/验收**：S/M。编辑一份现有集合不新建重复记录；应用与保存同一条件得同一结果；一个含 OR 和 NOT 的组合正确。

#### G2-15 执行契约

- 明确应用、编辑、另存为三种动作；编辑传现有 filterId，草稿枚举不能为空但假装已选。
- 定义保存集合与普通筛选叠加的规则，并在 Core 同一查询路径落实或在 UI 禁用叠加。
- 对缺失元数据的 NOT/不等于定义空值语义，Version Family 与复核/重复类型用结构化字段而非任意 JSON。
- **交付记录**：列出涉及文件、旧/新行为、实际执行的最小验证、失败或未验项；仅满足本节原有验收并给出证据后标记完成。

### G2-16：标签、收藏和整理结果保真

**证据**：`database.rs::add_asset_tag_batch/remove_asset_tag_batch/set_favorites_batch`、`cards.rs::CardManifest/CardIdentityHint`、扫描恢复逻辑。

**保留**：用户标签优先、用户删除阻止自动重加、批量数据库事务、来源与 confidence 记录，现有实现不需重造。

**修改方案**：

1. [确认] 卡片只有 `tags: Vec<String>`，重建库无法恢复每个标签的原 source/confidence。增加向后兼容 `tag_assignments`，包括 name/source/confidence；旧 cards 恢复时标记来源未知或采用明确兼容策略，不能伪造为 user。
2. [确认] 标签/收藏修改只令卡过期，尚未同步到旁车时删除数据库会丢失这些最新修改。增加有界 manifest 同步队列与“已保存到索引/已同步卡片”状态，写入失败可重试。遵守用户触发的整理范围，不追加自动 Agent 标签。
3. [设计] 标签输入改为带建议的就地输入，显示来源与置信度详情；批量操作保留现有全有全无语义，并在失败时显示相关资产。
4. [缺口] 标签作为一级导航补标签列表、使用数量及快速筛选。重命名/合并标签先做计划影响预览，保留 user override，不擅自合并同义词。
5. [设计] 收藏操作局部更新；“取消收藏”提供短时撤销，仅恢复 Library 状态。不要为一次收藏重绘图片或重载首屏。

**范围/验收**：UI S，卡片来源扩展与同步 M。临时库中增加 user/agent 标签、删除覆盖和收藏，写卡后重建，逐项比对；未同步状态必须明确可见。

#### G2-16 执行契约

- tag_assignments 以可选字段向后兼容，source/confidence 与用户删除覆盖可被重建；旧卡来源标 Unknown。
- 数据库成功但旁车未同步时展示待同步并保留重试；同步只改 manifest 时保持 preview 不变。
- 标签重命名/合并先展示影响计划，不自动合并近义词；用户手改优先于 Agent/解析器。
- **交付记录**：列出涉及文件、旧/新行为、实际执行的最小验证、失败或未验项；仅满足本节原有验收并给出证据后标记完成。

### G2-25：整体易用性、窗口适配和键盘交互

**证据**：`App.tsx` 的 JSX、`styles.css`、`tauri.conf.json`。本节是源码推断的设计改进，不包含实际截图或对比度合规结论。

**修改方案**：

1. [确认] `@media (max-width:1060px)` 隐藏 `.avatar`，当前唯一设置按钮正使用此 class；窗口允许 1040px 宽。保留设置入口或移入溢出菜单，用户在最小窗口也能选择动作预览模型。
2. [确认] 侧栏 storage-track 在有 Root 时固定 42%，索引“就绪”只看 busy，不反映 activeScans。换为真实容量或删除装饰进度；索引状态从后台摘要派生。
3. [设计] 保留 Steam Library 三栏。无选择时允许收起 Inspector；窄窗口详情改抽屉，搜索与主要动作保持可达。不要仅压缩字号解决拥挤。
4. [确认] 多种表单使用 window.prompt/confirm。逐步替换为可校验、可保留输入的应用内对话框；类型用选项、目录用选择器、批量标签用建议列表。
5. [确认] 多个 modal 有 aria-modal 但无统一焦点约束/恢复逻辑；只有部分查看器/菜单处理 Escape。抽取通用对话框，初始焦点、Tab 循环、Esc、关闭后回触发器；执行不可中断操作时解释关闭与取消差别。
6. [设计] 网格键盘导航、菜单键/Shift+F10、Enter 打开、Space 选择、Ctrl+F 搜索；与文本输入及 Viewer 快捷键隔离。正确设置 tab/aria-selected，按钮用可读名称。
7. [确认] 已有 reduced-motion CSS，继续保留；不少关键进度文字约 10.5px，建议提升正文与错误字号。实际可读性、对比度和高 DPI 裁切留到用户安排的 UI 验证。
8. [设计] 空状态分开：未添加 Root、已添加未扫描、扫描进行中、筛选无结果、Root 离线、加载失败。每种只给相关下一步，不都引导再添加目录。

**范围/验收**：以 S 为主。后续仅需最小窗口＋常用 DPI 下检查设置、搜索、详情；键盘走完一次添加/取消对话框。此轮不主动启动 UI。

#### G2-25 执行契约

- 先修 1040px 合法最小窗口设置入口，再调整抽屉/溢出布局；主动作在窄窗仍能找到。
- 对话框统一初始焦点、Tab、Esc 和关闭后回焦；不可中断后台操作的关闭语义要明确。
- 索引进度取真实后台状态；空状态按未配置、扫描中、无结果、离线和加载失败分别给下一步。
- **交付记录**：列出涉及文件、旧/新行为、实际执行的最小验证、失败或未验项；仅满足本节原有验收并给出证据后标记完成。
