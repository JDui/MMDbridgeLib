# 扫描自动标签与视觉标签

## 行为与职责

扫描默认启用技术标签，角色缩略图完成后默认提取整体色。设置中提供两个独立开关；关闭后保留已有标签，暂停该阶段的新增与更新。CLI 共用设置：`mmdbridge settings auto-tags --technical true --colors true --json`；不传开关时只读取。

| 内容 | 执行者 | 依据与时机 |
| --- | --- | --- |
| `资产:模型/动作/场景`、`格式:PMX/PMD/VMD/VPD` | Core 扫描 | 实际根类型和成功解析的格式，不等同于角色/服装/道具语义 |
| PMX 骨架分类、物理、SDEF/QDEF、Morph 及其类型 | Core 扫描 | 当前解析结果；PMD base morph 不算可用 Morph；不判断体型、裙型或身份 |
| 骨骼、表情、镜头、灯光、IK、自阴影轨道、静态姿势 | Core 扫描 | VMD/VPD 实际轨道与时间分布；隐藏纯镜头资产不生成普通标签 |
| `整体色:蓝色` 等主要色系 | Core 缩略图 | 当前角色主体的可见颜色，最多三种；不对动作参照角色或场景产生角色颜色标签 |
| 裙型、裙长、腰型、服装、发型、鞋型、配饰、模型角色 | Agent Skill | 用户明确授权标签任务后，逐项查看已有资源卡缩略图；看不清的项留空 |
| 发色、服装色、穿搭风格、可靠身份/系列 | Agent Skill | 识别具体可见区域和可靠证据，不把整体色复制为部位色或从文件名猜款式 |

软件不启动外部 Agent、不上传素材。扫描与缩略图阶段在软件内自动执行；视觉语义阶段由 `skills/mmdbridge-card-manager` 承接已经授权的扫描＋标签任务。当前环境没有实际资产库，因此此次不会声称真实素材已完成视觉标注。

## 颜色估计

在 Core 原始 RGBA 渲染完成后、WebP 有损编码前分析，以四角一致的背景色排除背景与接近背景的轮廓混合像素。每隔四像素采样，至少需要 300 个有效主体样本；选择占比至少 18% 的前三种颜色家族，主要家族合计不足 55% 时不自动写标签。技术事实置信度为 1.0；颜色启发式置信度为 0.78，均不表示经过校准的统计概率。

缺失/读取失败/超出预算的贴图、缺失依赖、背景不确定、主体过小和分散色彩跳过写入。真实白色无贴图材质可以得到白色；缺失贴图的白色回退不能。估计包含皮肤、头发及道具，并受原材质、toon、sphere map 和照明影响，不是精确固有色或服装颜色。Matcap 和场景渲染预设只影响查看器，不参与该颜色分析。

旧版但当前的资源卡可解码现有 WebP 得到保守颜色估计，无需重新启动 GPU。渲染报告保存 `subjectPalette`（算法版本、状态、有效样本数和颜色占比），旧报告缺少该字段仍可读取。

## 重扫和覆盖规则

自动标签沿用 `parser` 来源，并在现有 metadata 表记录各阶段实际拥有的标签名、算法修订和源指纹。重扫仅撤回本引擎拥有且仍是 parser 来源的过期事实，不改手动、Agent 或历史未托管标签；重新解析会清空托管的旧颜色，等待当前缩略图结果。用户改为手动来源后不再由引擎替换。手动移除覆盖继续阻止程序和 Agent 加回同名标签。已有手动 `整体色:` 标签时，程序撤回托管整体色并让出该维度。

相同标签/来源/置信度再次写入不会反复修改数据库或把资源卡变旧。仅标签/收藏变化造成的 CardStale 可以复用当前缩略图；复用必须同时满足源指纹、解析元数据、渲染版本及预览设置一致，贴图依赖或解析修订变化不能借此复用旧画面。颜色写入后重新读取卡片上下文；卡片仍按现有发布前检查防止并发修改覆盖。

PMX 解析修订升至 4，PMD 升至 3，用于补齐 SDEF/QDEF 和可用 Morph 分类。首次扫描旧模型会按既有规则刷新解析；VMD/VPD 旧记录可在无变更分支补齐技术标签。

## Skill 与验证

Skill 将裙装分成 garment、长度、轮廓、褶饰、腰型、结构等维度。百褶/A 字可兼容，互斥裙长不能随意并存；裙裤、披风、长外套、纹理线条、姿势导致的假开衩均需可见结构支持。裙型子类要求至少 0.8 的视觉置信判断；8–16 个标签不是配额，达到 20 个现有标签后停止 Agent 新增，不删除旧标签。

- 本地前端 15 项功能检查、TypeScript/Vite 构建、脚本语法及 Skill 格式检查通过。
- 独立 Skill 前向检查查看两张实际 Core 合成缩略图，保留手动红色标签，报告颜色冲突，拒绝仅凭文件名生成校园/Lolita/百褶裙标签，并将嵌入的指令文字视为数据。没有 CLI 可执行文件，该检查只输出候选与命令，没有数据库写入。
- Rust/CLI 的重扫、用户覆盖、颜色、缓存和 Windows 编译由 CI 验证；结果待运行后补录。
- `tagging_probe` 使用独立临时目录中的合成 PMX 和蓝色纹理，验证扫描标签、缩略图颜色、缺失贴图跳过、移除覆盖、手动色系、原图复用及卡片有效性；`tagging-review.mjs` 使用该 Core 输出拍摄扫描、颜色完成和设置三个阶段，验证开关持久化及失败保存。
